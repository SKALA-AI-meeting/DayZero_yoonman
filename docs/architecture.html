01 / SYSTEM OVERVIEW

업무의 기준은 Backend,
AI 실행은 별도 Worker

현재 Day Zero는 Next.js 웹, FastAPI Backend, AI Worker, Report Worker, Business MCP, RAG MCP를 분리한 로컬 MVP입니다. Python 서비스는 하나의 패키지와 이미지를 공유하며, PostgreSQL과 RabbitMQ를 공통 기반으로 사용합니다. 팀장·동료·개인 AI는 하나의 AI Worker 안에서 각각 독립 LangGraph로 컴파일됩니다.

이 문서의 기준

2026년 10월 20일, 커밋 930624a와 현재 미커밋 변경을 포함한 작업트리 코드·Compose 설정을 읽었습니다. 현재 프로세스의 실행 여부, 실제 모델 호출 성공, 전체 Docker 구동과 120분 세션을 이번 작업에서 재검증한 것은 아닙니다.

하나의 업무 원본

인증, 세션 시간, 수신자 결정, 문서·태스크 변경, 이벤트와 결과 저장은 Backend가 검증합니다. Worker와 Business MCP는 내부 HTTP API를 거쳐 업무를 요청합니다.

세 에이전트의 독립 실행

leader, colleague, chat은 Graph 템플릿을 공유하되 기억, 체크포인트 thread, 작업 순번, 실행 리스를 분리합니다.

제출 후 확정 입력 분석

세션 종료 때 snapshot v2를 고정하고 미완료 AI 작업을 취소합니다. 별도 Report Worker가 이 입력을 분석하고 Backend 검사를 통과한 리포트를 공개합니다.

Compose 배치

Python 역할은 같은 이미지로 실행됩니다. AI Worker는 Backend와 두 MCP 서비스 시작 후, Report Worker와 Web은 Backend 시작 후 구동합니다. pgdata, rabbitdata, models 볼륨을 사용합니다.

로컬 직접 실행

현재 scripts/dev.sh는 DB·큐를 Docker로 올리고 Python 프로세스 5개를 호스트에서 시작합니다. 웹은 별도 npm run dev입니다. 로컬 MCP 기본 바인딩은 127.0.0.1입니다.

시작 조건의 의미

DB·큐는 healthcheck, 마이그레이션은 완료 조건을 사용합니다. Backend·MCP 의존은 service_started이므로 실제 요청 준비나 모델 캐시·색인 준비까지 보장하지 않습니다.

03 / REQUEST FLOWS

대화, 문서 검색, 제출이
각각 처리되는 경로

① 메시지 입력 → 에이전트 응답

1. 웹에서 전송

메신저 팀 채널·동료 DM·개인 AI 흐름을 지정하고 고유 operation ID를 보냅니다.

2. Backend 접수

지원자 토큰·세션 상태·수신자를 검사하고 메시지와 에이전트별 Job을 같은 트랜잭션에 저장합니다.

3. 큐와 작업 획득

publisher가 Job ID를 RabbitMQ에 발행합니다. Worker는 내부 claim API에서 실행 리스와 작업 토큰을 받습니다.

4. Graph 실행

허용 문맥을 읽고 모델의 응답 또는 도구 제안을 받습니다. 도구는 Harness 검사 후 MCP를 거쳐 실행합니다.

5. 결과 검증·반영

Backend가 발신자·리스·공개 자료·변경 근거·이벤트 버전을 확인해 결과를 기록하고 웹이 최신 상태를 받습니다.

실시간 화면은 WebSocket으로 전체 workspace snapshot을 반복 전달하는 구조입니다. 지원자 화면은 5초 REST 조회도 병행하고, 연결 종료 시 2초 후 재접속합니다. 기업 목록·리포트 대기는 3초 조회를 사용합니다. 토큰은 WebSocket URL에 넣지 않고 연결 후 첫 메시지로 전송합니다.

② 회사 정보 질문 → 근거 문서 반환

1. 허용 도구 제안

Graph가 search_documents 또는 get_document를 제안합니다.

2. 공개 범위 확정

RAG MCP는 작업 토큰으로 Backend에 문서를 요청합니다. 기업·시나리오·공개 시점·승인 조건을 적용합니다.

3. 벡터 검색

로컬 BGE-M3가 1024차원 질의 벡터를 만들고, 허용 문서 ID 안에서 pgvector 코사인 거리 상위 3건을 조회합니다.

4. 출처 보존

공개 문서 원문과 ID·버전을 반환합니다. Graph 응답의 출처와 Backend 저장 시 출처 범위를 다시 검사합니다.

현재 색인은 문서 본문 전체를 한 벡터로 저장합니다. 별도 청크 테이블·reranker는 없습니다. 검색 서버는 다운로드된 모델을 local_files_only=True로 읽으며, 캐시나 색인이 없을 때 다른 검색 방식으로 자동 대체하지 않습니다.

③ 제출 또는 120분 마감 → 기업 리포트

1. 종료와 고정

Backend가 세션을 completed로 바꾸고 문서·대화·태스크·이벤트·모델 binding·기록 누락을 snapshot v2에 고정합니다.

2. 후속 AI 차단

대기·실행 중인 대화 작업을 취소하고 reports Job을 등록합니다.

3. 별도 분석

Report Worker가 snapshot을 받아 규칙 기반 근거를 구성하고 도구 없는 모델 호출로 관찰 문장을 생성합니다.

4. 공개 전 검사

원문·주체·ID·최종본·조건을 검증합니다. 통과하면 report_ready, 재시도 한도 소진 시 failed가 됩니다.

04 / AGENT EXECUTION

공통 Graph 템플릿,
독립 기억과 실행 권한

AI Worker는 세 Graph를 각각 컴파일하고 {session_id}:{agent_id}를 thread ID로 사용합니다. 같은 에이전트 안에서는 순번과 리스로 작업을 직렬 처리하며, 다른 에이전트는 독립적으로 진행할 수 있습니다. 현재 작업과 일치하는 미완료 체크포인트만 재개합니다.

load_context

respond / teammate_work

일반 대화 또는 동료 업무 계기를 처리합니다. 모델은 최종 답변이나 도구 제안을 반환합니다.

tools → 반복

허용 도구와 스키마·호출 예산을 검증하고 MCP를 실행한 뒤 응답 노드로 돌아갑니다.

guard → persist

출처·금지 표현·실제 변경 근거를 검사합니다. 필요 시 제한된 보정 후 Backend에 저장합니다.

세 에이전트 모두 remember로 자신에게 공개된 근거에 연결된 개인 메모를 저장할 수 있습니다. 따라서 팀장·개인 AI의 “조회 권한”은 업무 원본 변경 제한을 뜻하며, 개인 기억 기록까지 금지하는 것은 아닙니다. 미래 이벤트 원문과 비공개 자료는 문맥에서 제외됩니다.

동료의 실제 작업

현재 미커밋 구현은 분업 합의 후 동료 담당 파트에 태스크와 업무 계기를 자동 등록합니다. complete_task는 문서 내용과 태스크 완료를 함께 저장합니다. 재조율 시 이전 자동 태스크·대기 작업을 정리합니다.

실행 한도

Job당 도구 호출은 최대 3회입니다. Backend는 AI 모델 시도 6회, 리포트 모델 시도 3회를 제한합니다. 전체 Job 실행 기한은 최초 시작부터 450초이며 heartbeat로 리스를 갱신합니다.

고정 모델 경로

세션 시작 시 binding과 report_binding을 따로 고정합니다. 기본 API 모델은 gpt-4o-mini이며 리포트 전용 설정을 생략하면 에이전트 설정을 상속합니다. 실패 시 다른 공급자로 자동 전환하지 않습니다.

접수와 발행 분리

jobs.published=false가 DB outbox 역할을 합니다. publisher는 0.5초 간격으로 대기를 확인하고 durable 큐에 persistent 메시지를 확인 발행합니다.

리스 기반 회복

claim은 45초 리스를 발급하고 Worker는 5초마다 heartbeat를 보냅니다. 리스 만료 Job은 pending으로 되돌아갑니다. 재시도 가능한 실패는 작업 시도 3회 미만에서 다시 대기합니다.

중복·늦은 결과 차단

선택 경로인 Codex CLI 격리

CLI 어댑터는 현재 macOS arm64, 지정 CLI 버전, macos-seatbelt-v1 프로파일에 한정됩니다. 호출마다 임시 디렉터리를 만들고 사용자 설정·규칙을 가져오지 않으며 native 도구를 비활성화합니다. OS 정책은 지정 실행 파일·인증 파일·임시 런타임을 허용하고 셸 등 다른 프로세스 실행을 제한합니다. 네트워크는 모델 접속을 위해 허용됩니다.

자식 환경에 제품 API 키를 상속하지 않고 기존 로그인 파일은 임시 런타임에 심볼릭 링크로 연결합니다. 모델 출력은 도구 제안일 뿐이며 실행은 계속 외부 Harness가 담당합니다. 지원하지 않는 OS·버전·프로파일은 실패하도록 구현되어 있습니다.
